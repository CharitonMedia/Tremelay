Tremelay

A local credential broker, so your AI agents can use your credentials without ever seeing them.

Status: v1.0.2, released 2026-10-15. Single user, local only, and not independently audited.

Why

You already give agents real authority: read these issues, push this branch, call that API. Today that means pasting a token into a config file, an environment variable, or an MCP server, and hoping nothing logs it, echoes it, or wanders off to the wrong host with it.

Tremelay splits possession of a secret from authority to use it. You keep credentials in a local encrypted vault. Each agent gets its own identity and its own narrow, expiring, revocable grants — “GET anything under https://api.github.com/repos/you/yourrepo with this token”, “authenticate to git.example.com as git with this SSH key”. The agent asks Tremelay to perform the operation; Tremelay performs it with the credential and returns only the result the grant allows. The agent never receives the secret, there is no getSecret tool to call, and every attempt — allowed or denied — lands in a hash-chained audit log.

The broker possesses secrets. Agents possess capabilities.

Agents connect over MCP (list_capabilities, describe_capability, invoke_capability), or over an ssh-agent socket for SSH signing. Everything is local: one SQLite vault file, one user-only socket or named pipe, no server, no account, no telemetry.

How it works

Install

Tremelay needs the pinned Go toolchain (1.26.9, see go.mod); go install switches to it for you.

go install github.com/CharitonMedia/Tremelay/cmd/tremelay@v1.0.2

From a clone, make build or go build ./cmd/tremelay does the same thing. The v1.0.2 release carries per-platform archives, a CycloneDX SBOM and a SHA256SUMS file — a checksum detects a corrupt download, not a substituted release. Signed releases are not in v1.

The shape is the same everywhere. tremelay daemon --vault PATH asks for your passphrase once in your terminal and then serves agents on a user-only local socket; tremelay agent create --token-file FILE gives each agent its own bearer token file, and tremelay agent token issue|rotate|revoke manage it later without recreating the agent; tremelay mcp --daemon --token-file FILE is the stdio command the client launches. tremelay lock, the idle timeout, or losing the process zeroises the key.

What it does not do

Read this before you trust it with anything.

  • One human. Single user, single vault. No multi-user, no orgs, no shared vaults, no team policy.
  • One machine. A user-only Unix socket or Windows named pipe, and stdio; there is no network or remote MCP transport. tremelay ssh-agent is Linux and macOS only and fails closed on Windows.
  • The agent still reads broker responses. An http_broker grant returns the status code, an allowlisted set of response headers, and up to 32 KiB of the body with the credential redacted in its common encodings (raw, URL, base64, hex, JSON-escaped). The agent never sees the credential, but it does see the data that credential unlocks — and anything in that body can be prompt injection. A hostile upstream that deliberately re-encodes or splits the credential is not caught; grant only origins you trust with the credential.
  • An unlocked daemon trusts your uid. While it is unlocked, any code running as you can use your agents' granted capabilities. It still cannot read a credential, change a grant, or learn your passphrase, and everything it does is audited — but that is the boundary.
  • No OAuth refresh brokering, no database session brokering, no browser form fill, no TOTP, no provider-assisted rotation. These are in VISION.md and on the roadmap, not in v1.
  • Legacy GitHub issue grants block unlock. A vault that still holds a pre-v1 github_issue_state grant will not unlock until that grant is revoked with the pre-v1 binary.
  • No third-party audit. No independent security review and no signed releases yet. The audit chain is tamper-evident to you; nobody else checkpoints it.
  • credential get prints the raw secret. That is the human control plane, by design — it is not reachable from any agent interface.
