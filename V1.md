# Tremelay v1 — Finish Line

This file is the single definition of done. If work is not on this list, it is not v1.
Items are done in order unless marked independent. Check a box only when its
acceptance line is demonstrated on the `v1` branch with CI green.

## Who v1 is for

One human, many agents. People running Claude Code, Codex, Hermes, Grok bots and
similar agents who want those agents to *use* API keys and SSH keys without ever
*seeing* them.

## Decisions (Patrick, 2026-10-13)

- Single user with multiple agents. Multi-user and shared vaults are out of v1.
- The agent build/review automation over-engineered the project; it is frozen.
- Native-client test acceptance: the test passes and observed behavior is
  documented. No causal proofs about third-party client internals.
- Target audience: agent users. Get to 95%, then open-source and maintain.

## Non-negotiables (unchanged from AGENTS.md)

No agent-facing raw-secret retrieval. Deny by default. Every credential-backed
attempt is audited. No secrets in logs, errors or fixtures. No invented crypto.

  *Accept:* CI green; README and MILESTONES no longer mention shared vaults.
- [x] **3. Headless unlock (DECIDED — Patrick 2026-10-13: unlock once, then agents connect).**
  Agents run unattended, so a per-launch pinentry prompt does not work for the
  target user. Build `tremelay daemon`: the human unlocks once in a terminal; the
  daemon holds the vault in memory on a user-only Unix socket / Windows named
  pipe; each agent gets its own token file from `tremelay agent create`;
  `tremelay mcp` (the stdio command the client launches) connects with that
  token. Locks on `tremelay lock`, a configurable idle timeout, or reboot.
  Accepted tradeoff: while unlocked, a compromised machine can use agents'
  authority, but keys never leave the daemon. Pinentry stays as an option, not
  the default agent path. Needs an ADR.
  *Accept:* Claude Code and Hermes each call a capability with no prompt after
  the daemon is unlocked; locking the daemon makes the next call fail closed;
  a wrong or revoked agent token is refused and audited.
- [x] **4. A useful HTTP broker.** Grant = origin + allowed methods + path
  prefix + injection style (bearer, named header, basic, query param). The
  agent supplies method, path under the prefix, query, body and non-auth
  headers; it receives status, an allowlisted set of response headers and the
  body (size-capped), with any occurrence of the credential redacted. Keep
  existing SSRF, rebinding, proxy and redirect defenses. The GitHub issue-state
  special case becomes an ordinary HTTP grant. ADR required.
  *Accept:* an agent lists and reads GitHub issues and calls one other real API
  through MCP; adversarial tests show the credential never appears in output,
  audit or errors, including when the server echoes it back.
- [ ] **3b. Windows daemon (Patrick 2026-10-13: "we need windows ... it is the
  largest pool").** Reverses ADR 0024's Windows deferral. `tremelay daemon` and
  `tremelay mcp` work on Windows over a named pipe restricted to the current
  user (owner-only DACL, reject remote clients), same token, lock, idle-timeout
  and fail-closed behavior as Linux/macOS. Amend ADR 0024. Pinentry stays an
  option. No causal proofs about third-party client internals; observed
  behavior is the bar.
  *Accept:* windows-latest CI runs the daemon end to end (unlock, agent call,
  wrong token refused and audited, lock fails closed); and Claude Code calls a
  capability through the daemon on a real Windows machine of Patrick's
  (laptop via `ssh laptop`, or Desk), recorded in docs/evidence/.
- [x] **3c. Never make the user rebuild an agent (Patrick 2026-10-13: "I would
  rather delete this program than have to rebuild a fucking agent.").** Hard
  rule for all of v1: no Tremelay operation may require deleting or recreating
  an agent, or editing the real agent's (Hermes/Claude/Codex) MCP config.
  - `tremelay agent token issue --agent ID --token-file PATH` gives a token to
    any existing agent, including agents created before the daemon existed.
  - `tremelay agent token rotate --agent ID` writes the new token to the same
    token file path, so the real agent's config never changes; the old token is
    refused immediately, including in a running daemon.
  - `tremelay agent token revoke --agent ID` cuts off the token; the agent keeps
    its id and grants and gets a new token with `issue`.
  - Every one is audited. Amend ADR 0024 (drops "revoke and recreate").
  *Accept:* on Linux and Windows CI with the daemon running and no restart: a
  pre-daemon agent gets a token and works; rotate keeps the same file path and
  grants, old token refused and audited; revoke then issue restores access
  with the same grants. Review every doc and error message for any instruction
  to recreate an agent and remove it.
- [x] **3d. Daemon reloads in place on control-plane change (Patrick
  2026-10-13: "2a").** Reverses ADR 0024's zeroise-and-exit on stale session.
  When the human CLI changes agents or grants, the running daemon re-reads the
  vault with the key it already holds, re-verifies the sealed audit head, and
  keeps serving; agents are not interrupted and new grants/revocations apply
  immediately. If verification fails, it locks fail-closed as today. Amend
  ADR 0024.
  *Accept:* with the daemon unlocked, `grant create` makes the grant usable and
  `grant revoke` makes it refused, with no restart and no passphrase re-entry;
  a tampered vault file makes the daemon lock. Linux and Windows CI.
- [x] **5. SSH signing for agents.** `tremelay ssh-agent` exposes an

  `ssh_userauth` grant (user + pinned host key). *Accept:* `git push` over SSH
  to a test repo works through the socket; revoking the grant stops it.
- [ ] **5b. SSH works with GitHub (Patrick 2026-10-13: "S1 yes").** In addition

## Accepted limits (Patrick 2026-10-13, state them in README)

- H1: HTTP response content is not screened for prompt injection; the broker
  keeps the credential out, not hostile instructions.
- H2: a vault holding a legacy `github_issue_state` grant will not unlock until
  that grant is revoked with the pre-v1 binary.

## Out of v1 (community roadmap)

Multi-user/orgs, OAuth refresh brokering, database session brokering, browser
form submission, TOTP, provider-assisted rotation, remote/network MCP transport,
signed releases and an independent security audit.
